METHOD
  .text is split into functions at int3 padding and each is disassembled
  LINEARLY from its real start, so instruction boundaries are correct. An
  earlier version guessed boundaries by scanning backwards from each 4-byte
  reference, which produced ~68 nonsense decodes (`add byte ptr [ecx+...]`)
  that are absent here.

  Each reference is then classified by how the episode value is used, and the
  compared constant resolved where it is not literal - for `cmp [g], reg` by
  walking back for the `mov reg, imm` that loaded it, and for a load by
  walking forward to the `cmp`/`test` that consumes it.

  'Opened by TACE' comes from simulating main.cpp's patches IN SOURCE ORDER
  against a copy of .text. That matters: patches overwrite each other, and a
  scan of the untouched exe gets this wrong.

READ THIS BEFORE OPENING ANY OF THEM
  A gate is content the game runs only in one episode; opening it makes that
  content unconditional. NOT every gate should be opened. Many choose between
  two equally valid per-episode values - a constant, a model name, a sound -
  and forcing one overrides the other episode's. We already hit this: a patch
  labelled 'E2 Bullet traces' was landing on a `cmp episode,1` choosing
  between the PU_SEADONE and PU_SEADONEE2 pickup names, pinning a pickup name
  in every episode for no benefit.

  `cmp episode, 3` is a bounds check - there is no episode 3. Ignore those.
  Only cmp-imm gates are openable by NOPing the jump. cmp-reg and load-cmp
  need the surrounding code read first; the branch may be shared.

  Still outside this file (you said exe-only, noting it so nobody assumes):
  SCM script checks via GET_CURRENT_EPISODE, rpf.xml mounting, and per-episode
  .dat/.img data gate a great deal of content that no code scan will find.
